# 설계 판단

[README](../README.md)로 돌아가기

검토 끝에 "하지 않는다"로 정한 것은 근거를 남겨 둡니다. 근거가 없으면 같은 논의를 몇 달 뒤 처음부터 다시 하게 됩니다. 여기 옮긴 판단을 관통하는 원칙은 하나입니다. 관측 hub는 홈랩에서 가장 지루해야 하는 호스트입니다. 다른 것이 다 망가져도 살아서 보여 주는 것이 이 호스트의 일입니다.

## 관측 hub를 쿠버네티스로 옮기지 않는다

docker compose로 돌리는 관측 스택을 단일 노드 쿠버네티스(RKE2)로 옮기는 안을 검토했습니다(2026-08). 기술적으로는 전부 옮길 수 있었고, 오버헤드(메모리 1.5~2GB, CPU 0.3~0.5코어)도 감당할 수 있었습니다. 막은 것은 자원이 아니라 다음 두 가지였습니다.

- 관측의 사각지대가 생깁니다. compose는 무엇이 터져도 `docker ps`와 `docker logs`로 상태를 볼 수 있습니다. 쿠버네티스는 API 서버가 죽으면 한 단계 아래 도구로 내려가야 하고, 하필 그때가 다른 것도 안 보이는 시점입니다.
- 작업 디렉터리가 곧 라이브 상태라는 단순함이 깨집니다. 알람 룰 한 줄을 고쳐도 ConfigMap 갱신과 롤아웃이 필요해지고, ConfigMap 1MiB 상한에 대시보드 디렉터리가 걸립니다.

얻는 것은 클러스터와의 도구 통일뿐이고, 단일 노드라 가용성이나 확장성은 하나도 늘지 않습니다. 쿠버네티스 운영 경험은 [6노드 클러스터](kubernetes.md)가 맡습니다. 선언형 관리가 필요해지면 순서는 클러스터에 GitOps를 먼저 굳히고, 그 모델이 자리 잡은 뒤 hub를 선언형으로 바꾸는 것입니다. 그때도 쿠버네티스일 필요는 없습니다.

## VictoriaMetrics를 Mimir로 바꾸지 않는다

"수집기를 Grafana Alloy로 쓰니 저장도 Grafana 계열(Mimir)로 가야 한다"는 연결은 성립하지 않습니다. Alloy는 저장소를 가리지 않습니다. 쟁점은 저장소 자체였습니다.

- VictoriaMetrics의 실측이 좋습니다. 샘플당 0.42바이트, 메모리 1.1GB, 91일치 5.1GB입니다(2026-08). Mimir는 블록 저장과 객체 스토리지가 사실상 전제라 디스크가 통상 3~5배 듭니다.
- Mimir의 설계 목표(수평 확장, 멀티테넌시, 객체 스토리지)는 이 규모에 해당하지 않습니다. 대신 잃는 것은 구체적입니다. 원격 push를 받는 인증 관문(vmauth)과 룰 엔진(vmalert)을 다시 만들어야 합니다. Mimir의 테넌트 헤더는 인증이 아니라서 앞단 프록시가 따로 필요합니다.
- "멀티테넌시가 필요하면 Mimir"도 틀린 전제입니다. VictoriaMetrics에도 클러스터판에 테넌트 구분이 있습니다. 지금 쓰는 단일 노드판에 없을 뿐입니다.

다시 볼 조건도 정해 두었습니다. 실습 플랫폼처럼 여러 사용자가 한 저장소를 나눠 쓰는 일이 현실이 될 때입니다. 그때도 저장 격리가 필요한지, 조회 권한 분리로 충분한지를 먼저 가립니다.

## 분산 트레이싱(Tempo)은 찬성, 저장소는 그대로

트레이스는 메트릭 저장소와 무관하게 붙일 수 있고, 배선 절반은 이미 있습니다. 로그에서 `trace_id`를 뽑아 링크로 만드는 Grafana 설정이 있고, 클러스터의 MCP 서버와 ratatosk.io 웹 서버가 같은 `trace_id`를 남기는 것은 2026-07에 끝에서 끝까지 확인했습니다. Tempo를 세우면 링크 대상만 바꾸면 됩니다. 남은 것은 kagent의 Go 런타임이 트레이스 문맥을 전달하지 않는 문제(upstream 기여 후보)입니다.

## 원격 사이트는 push, 받는 문은 하나

원격 사이트마다 hub가 가져오는 구조였다면 사이트마다 들어오는 방향을 열어야 합니다. 원격이 보내는 구조는 나가는 방향 한 줄이면 됩니다. 받는 쪽은 인증 관문 하나로 모으고, 사이트마다 토큰과 허용 경로를 따로 둡니다. 상세는 [관측 스택](observability.md#원격-사이트와-수신-관문)에 있습니다.

## 공용 서비스를 관측 호스트에서 분리

한때 hub에서 SSO(Keycloak)와 쿠버네티스 관리(Omni)도 함께 돌렸습니다. 2026-09-02에 둘을 OCI 오사카의 별도 VM으로 옮겼습니다. 명분은 자원이 아니라 노출 구조였습니다. 한 호스트에 Cloudflare 프록시를 거치는 이름과 거치지 않는 이름이 섞여 있으면 프록시 뒤의 주소까지 드러납니다. 지금 hub에는 프록시를 거치는 이름 하나만 남았습니다.

## 배포: 서버가 git을 당겨 적용한다 (설계 완료, 적용 준비 중)

운영을 AI 에이전트에게 맡기려면 에이전트가 서버 셸 없이도 변경을 반영할 수 있어야 합니다. 배포의 유일한 입력을 git으로 만들고, 서버가 스스로 당겨 적용하게 하는 방식을 설계했습니다. 승인은 배포 도구가 아니라 PR 머지가 맡습니다.

| 방식 | 서버로 들어오는 연결 | 자격 정보가 닿는 범위 | 판정 |
|---|---|---|---|
| CI가 SSH로 밀어 넣기 | 필요 | GitHub이 서버 키를 가짐 | 가정망 서버는 불가. 기각 |
| self-hosted 러너 | 없음 | 러너 토큰이 곧 서버 셸 | 서버마다 러너, GitHub 종속. 기각 |
| 중앙 배포 도구(Komodo 등) | 중앙에서 각 서버로 필요 | 중앙이 뚫리면 모든 서버의 docker 소켓 | 한 담당이 다른 담당의 서버를 배포하는 구조. 기각 |
| 웹훅 수신 | HTTPS | 서명 비밀 | 공개 입구가 있는 서버만 가능. 즉시성이 필요하면 후보 |
| 서버의 pull 폴러 + 상태 메트릭 | 없음 | 읽기 전용 배포 키 | 채택 |

pull 방식의 약점으로 흔히 꼽는 폴링 지연은 문제가 아니었습니다. Argo CD와 Flux도 기본이 폴링입니다. 부족한 것은 "지금 어느 커밋이 적용돼 있고 마지막 시도가 성공했나"를 보여 주는 상태였고, 이것을 메트릭으로 내보내 기존 관측 스택에서 보고 알람을 겁니다.

동작 규칙은 이렇습니다.

- 서버 쪽 커밋이 원격보다 앞서 있으면 멈추고 알립니다. 앞으로 감기만 합니다.
- 서버에 커밋하지 않은 변경이 있으면 멈춥니다. 사람이 서버에서 작업 중일 때를 보호합니다.
- 적용 직전에 바뀐 파일 종류별로 검증(compose 설정, 알람 룰, Alloy 설정)하고, 실패하면 적용하지 않고 보류합니다.
- 적용 뒤 컨테이너가 모두 떴는지 확인하고 결과를 메트릭으로 남깁니다. 실행 주체는 systemd 타이머입니다. 컨테이너로 돌리면 배포 중에 자기 자신을 재생성하다 끊길 수 있어서입니다.

검증은 세 층으로 나눕니다.

| 층 | 예 | 언제 |
|---|---|---|
| 정적 | compose 설정, Alloy 설정, 알람 문법, 시크릿 스캔 | PR 자동 검사 |
| 읽기 실측 | 쿼리가 실제로 데이터를 돌려주는지(저장소 조회만) | PR, 에이전트가 결과를 본문에 첨부 |
| 적용 후 | 실제 기동, 설정 다시 읽기 수용 | 배포 직후 확인과 사람 눈 |

## 운영 규칙으로 굳힌 것

- 컨테이너 네트워크 모드는 역할이 정합니다. 수집기(Alloy)는 호스트 네트워크, 공개 입구(Caddy)도 호스트 네트워크로 두어 방화벽 지점을 하나로 모으고, 나머지 앱은 브리지입니다.
- 새 docker 네트워크는 서브넷을 명시합니다. 자동 할당된 대역이 VPN 너머 대역보다 구체적인 경로가 되어 전송이 7시간 끊긴 [사고](incidents.md)에서 나온 규칙입니다.
- 설정 파일은 디렉터리로 마운트합니다. `git pull`이나 대부분의 편집기는 파일을 새로 만들어 바꾸는데, 파일 하나를 마운트한 컨테이너는 옛 파일을 계속 붙들고 있습니다. 이때 설정 다시 읽기는 옛 내용을 다시 읽고도 성공했다고 기록합니다. pull 배포를 켜면 `git pull`이 정식 경로가 되므로 그 전에 막았습니다.
- 레포를 비공개로 바꾼 뒤에도 비밀 규율은 공개 때와 같습니다. 이미 공개된 커밋은 되돌릴 수 없고, 내용 일부는 블로그와 upstream PR로 계속 나가기 때문입니다. 커밋마다 시크릿 스캐너가 돕니다. 아는 단어를 나열하는 방식은 나열하지 않은 대역과 계정명을 원리상 못 잡아서, 값의 모양으로 판정하는 방식(대입형 비밀 값, 환경 파일에 있는 값, 허용 대역 밖의 IPv4, 커밋하는 사람의 계정명)으로 바꿨습니다.
